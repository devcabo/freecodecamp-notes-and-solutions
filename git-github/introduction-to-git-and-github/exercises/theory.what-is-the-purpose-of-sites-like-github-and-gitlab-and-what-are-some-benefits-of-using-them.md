## Module Overview

This module covers the differences between GitHub and GitLab, collaborative development workflows and project types such as open source software.

Open source projects allow people to view the source code, suggest changes, report issues and even create modified versions of the original project.

Platforms like GitHub and GitLab help developers collaborate more efficiently by sharing code changes in real time instead of manually sending files or explaining modifications separately.

This workflow improves:
- communication
- organization
- code review
- teamwork

Both platforms support features such as:
- repositories
- issue tracking
- pull/merge requests
- version control integration
- project collaboration

One important difference is that GitHub is more widely used in public open-source communities, while GitLab is strongly focused on integrated DevOps tools and self-hosted enterprise solutions.

Another key difference is terminology:
- GitHub uses Pull Requests
- GitLab uses Merge Requests

These systems allow teams to review and discuss changes before they are officially merged into the main project, making development safer and more organized.

This process is important because it encourages technical discussions, code analysis and collaborative problem-solving before changes are approved and published.

## Question 01

What is the main purpose of GitHub and GitLab as discussed in the lesson?

## Answer

Version control providers with collaboration features.

## Explanation

GitHub and GitLab are platforms built around version control systems, mainly Git, that help developers store, manage and collaborate on projects.

Their main purpose is to improve teamwork by allowing multiple developers to work on the same codebase in an organized and secure way.

These platforms provide features such as:
- repository hosting
- code sharing
- pull/merge requests
- issue tracking
- project management
- collaborative code reviews

Instead of manually sending project files between developers, changes can be uploaded, reviewed and discussed directly through the platform.

## Practical Example

```text
Developer A creates a new login feature and uploads the changes to GitHub.

Developer B reviews the code, suggests improvements and approves the changes before they are merged into the main project.
```

This workflow helps teams collaborate efficiently while maintaining project organization and code quality.

## Question 02

What is an advantage of using GitHub or GitLab for team collaboration?

## Answer

Team members can propose changes that others can review online.

## Explanation

GitHub and GitLab allow developers to share code changes online so other team members can review, discuss and approve them before they become part of the main project.

This improves collaboration by making communication more organized and reducing the risk of errors being added directly to the codebase.

The review process also helps teams:
- maintain code quality
- detect bugs earlier
- discuss better solutions
- keep project history organized

These platforms make collaborative development safer and more efficient, especially in large projects with multiple contributors.

## Practical Example

```text
A developer uploads changes to fix a bug in the authentication system.

Before the changes are merged, other team members review the code, leave comments and suggest improvements directly on the platform.
```

This allows the team to validate the solution and maintain code quality before publishing the update.

GitHub and GitLab provide project management tools that help development teams organize tasks, track bugs and monitor project progress.

Two common features are:
- issue trackers
- project boards

Issue trackers allow developers to report bugs, suggest improvements and assign tasks to team members.

Project boards help organize workflows by separating tasks into categories such as:
- To Do
- In Progress
- Completed

These tools improve communication, organization and productivity during software development.

## Practical Example

```text
A team creates an issue reporting a login bug and assigns it to a developer.

The task is then added to the project board under "In Progress" until the fix is completed and moved to "Done".
```

This workflow helps teams monitor project tasks and maintain organized development processes.
